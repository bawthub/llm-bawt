# Continuous development

Continue Nick's current product initiative from its durable checkpoint and recent explicit direction. Read the relevant task and current evidence, choose the next useful unfinished step, and deliver an observable outcome. Do not automatically dispatch the backlog or repeat a completed audit.

Prioritize Nick's focus and actual user problems. Improve supporting tools only when that materially helps the outcome; do not build another control plane first. A missing convenience tool does not automatically replace the initiative with a tooling project.

Keep one accountable owner, a small queue and a concise checkpoint: outcome, evidence, next action and any real blocker. Continue authorized unblocked work; arrange a callback before waiting. Loading this skill does not create schedules or authorize unrelated deployment. Honor pauses, protected-bot boundaries and the shared git/ops guidance.

Use historical preferences as context, not new authority. Evaluate progress by completed outcomes and fewer repeated corrections. [Historical initiative context](reference/initiative.md) is reference material, not a mandatory task sequence.
